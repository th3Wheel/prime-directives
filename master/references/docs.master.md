# Documentation and Markdown

- Write plain, specific sentences. Lead with what the reader needs to do or know.
- Markdown: one H1 per file, headings in order, fenced code blocks with a language tag, relative links for files in the repo.
- Lint Markdown with the shared ESLint `@eslint/markdown` setup.
- Update the README or relevant doc in the same PR as the behavior change. Keep `CHANGELOG.md` entries user-facing.
- Do not paste secrets, internal hostnames or personal data into docs or examples.
